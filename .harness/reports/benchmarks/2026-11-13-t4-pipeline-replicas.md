# T4 Nginx 多 Pipeline 性能与长尾验证

日期：2026-11-13（Asia/Shanghai）。本报告记录实验事实，不是生产容量承诺。

## 当前结论

固定 16 页、并发 8 的三次重复测量中，四 Pipeline 相对单 Pipeline 的成功页吞吐
中位数提高约 89.5%，P95 从 26.40 秒降到 19.50 秒。该集合的 240 次 A/B/C/D
计时请求全部成功并通过严格结构质量门槛。A/B/A 回归支持收益来自跨页并行。

这不意味着整书已验收：第 81 页存在算法块重复生成，单页独立耗时约 110 秒，
在单 worker 与四 worker 的八页并发诊断中均触发排队超时。结构验证器不会识别
正文重复。这一长尾不能用提高 token/s 或 GPU 利用率解释成有效产能收益。

四 worker 已完整尝试 407 页，401 页成功、6 页超时，因此整书零失败验收未通过。
单 worker 为 399/407 成功、8 页超时。四副本全量吞吐约 +81.3%，但新增四页超时，
不满足“不得新增超时”门槛。Ray Serve 未实施。

## 输入、时延与重试口径

样本为用户提供的 407 页《Generative AI on Kubernetes》，SHA-256：
`dd200b826db5f0bd78322944a4f341ec7dfe9fb0bb46ff244adee8769dba25e1`。
原 PDF 未改动。每次请求只提交一个拆分后的单页 PDF；最多 8 个在途请求，完成后补页。

固定页清单：1,2,3,6,7,8,30,40,80,120,160,200,240,280,320,360。
这个小集合覆盖文字、图示和代码，未覆盖表格，不能单独证明表格稳定性。
完整输入已经在前 80 页覆盖第 36/64/71 页的表格，相关 HTML 有开始及结束标签；全量 D 的 18 个表格另完成嵌套结构检查。

计时从发起请求开始，包含服务端排队及客户端归一化、质量校验；不包含源 PDF
拆页准备、模型启动与单独预热。每页客户端总期限保持 120 秒；Nginx 读超时也是
120 秒，但后者是相邻读取间隔，不是总预算。客户端不自动重试，Nginx 明确禁止
自动重发 POST。主测试直接调用 PaddleX 入口，不经过网关的默认传输重试路径。

A 组启动两个 worker 以固定副本内存，但 Nginx 将第二个标记 down，只路由一个；
B/C 启用两个，D 启用四个。Nginx least_conn 的连接数不代表内部真实队列长度。
每个新实验组通过 Compose 标签触发 worker 重建并单独预热，防止遗留队列污染；
共享 vLLM 不重启。容器自动重启在实验 overlay 中关闭，保留首个异常。

## 固定集合：三次独立计时

数值为三次测量的中位数；P95 先逐次计算，再取中位数。

| 组别 | 活跃 Pipeline | 每实例子图并发 | 成功页/秒 | 相对 A-pre | P95 秒 | 严格通过 |
| --- | ---: | ---: | ---: | ---: | ---: | ---: |
| A-pre | 1 | 16 | 0.3187 | 基线 | 26.40 | 48/48 |
| B | 2 | 8 | 0.4476 | +40.5% | 21.50 | 48/48 |
| A-post | 1 | 16 | 0.3201 | +0.5% | 26.87 | 48/48 |
| C | 2 | 16 | 0.4921 | +54.4% | 20.73 | 48/48 |
| D | 4 | 16 | 0.6038 | +89.5% | 19.50 | 48/48 |

D 相比 C 约提高 22.7%。D 同时把总子图供给上限从 32 增至 64，不能把这一差值
全部归因于保持相同子图并发上限时的页面重叠。B 与 A 的总供给上限均为 16。

冷启动 `cold-A` 的前 8 页有 8/8 请求成功、7/8 严格质量通过，最高延迟 54.25 秒；
不纳入上表。第 4 页源 PDF 文字、图片、内容流均为零，是空白页。

## DP 吞吐是否足够、为什么 Pipeline GPU 仍低

以下也是三次测量的中位数；GPU 为指定设备的采样平均值。token/s 来自约一秒间隔的
Prometheus 累计计数差，存在采样边缘与指标刷新误差，只作为辅助指标。

| 组别 | 合计 generation tokens/s | 合计平均 Running | 最大 Waiting | VLM 四卡平均利用率 | Pipeline GPU 平均利用率 |
| --- | ---: | ---: | ---: | ---: | ---: |
| A-pre | 118.5 | 2.17 | 0 | 33.4% | 6.1% |
| B | 166.0 | 4.59 | 0 | 40.2% | 4.6% |
| C | 181.3 | 4.12 | 0 | 41.1% | 5.6% |
| D | 225.2 | 8.67 | 0 | 43.5% | 4.0% |

四副本确实增加了后端供给，成功页吞吐与生成吞吐同步提高；但尚未形成 DP 持续排队，
不能声称后端已压满。Pipeline GPU 使用率低也没有随副本数成比例升高，不能仅凭它
断言 CV 计算是瓶颈，或判定需要增加 DP 数量。

第 81 页的 15 秒、25 Hz、含 idle 栈采样中，VLM worker 的 374 个有效栈样本全部位于
`_doc_vlm_genai_collect_responses -> Future.result -> wait`，Serving worker 在等待
Pipeline 结果队列。这证明了该诊断窗口中的等待路径；没有把全部 idle 线程的栈比例
当作 CPU 热点比例。长生成期间只有一个 DP rank 持续 Running，Waiting 为零。

四 Pipeline 常驻 GPU 1 显存一次采样为约 3307 MiB，每个进程约 826 MiB（预热后采样）；
这不是跨输入的容量保证。D 整书采样的 GPU 1 峰值也是 3307 MiB；VLM 四卡峰值
分别为 10995 / 9809 / 11377 / 10805 MiB。容器 RAM 采样约 1.3～1.5 GiB/worker、
VLM 约 10 GiB。全局 load1 平均 7.85、最高 12.69，相对 80 个逻辑处理器有 CPU 余量。

当前镜像实际读取 `layout_prep_cpu_workers`，源码把线程数限制为
`min(layout_prep_cpu_workers, num_pages)`。运行时为 use_queues=True、CPU workers=16；
本实验每个请求只有一页，该页面准备阶段的有效页面并行上限仍为 1，不能把配置 16
误解为单页同时由 16 个准备线程处理。

## 长尾复现与独立参数诊断

- 初次整书 `book-A-1`：80 页成功、81～88 共 8 页超时，319 页未提交。361.57 秒结束，
  不能用其页/秒计算完整整书提速。Nginx 记录 499，表示客户端总期限先到；没有引擎退出。
- `isolate-page81`，C=1：110.52 秒成功且严格结构验证通过。
- `isolate-range-A`，81～88、C=8：4/8 成功，4/8 超时。
- `isolate-range-D-1`，相同页面和 C=8：6/8 成功，2/8 超时。
- 第 81 页一个 algorithm 块输出 8640 字符、110 行、唯一行 16，某行重复 48 次；
  源页总文字 2229 字符、38 个非空行、最多重复 2 次。输出结构通过不代表内容正确。
- 经用户单独授权，仅第 81 页请求设置 repetitionPenalty=1.05：112.49 秒成功，
  本次没有改善默认请求的长尾。未修改服务默认参数，未扩大到其他页面或主性能对照。

现有证据支持长 VLM 生成叠加串行页队列造成超时。四副本减轻排队，但无法保证长页
落入 120 秒预算；least_conn 也不会知道客户端取消后仍可能存在的 worker 内部积压。

## 全量独立页面统计

两组显式开启健康后端的独立页超时后继续，D 先于 A 运行：

| 组别 | 已尝试页 | 成功 | 超时 | 严格通过 | 批次秒 | 成功页/秒 | P50 / P95 / P99 秒 |
| --- | ---: | ---: | ---: | ---: | ---: | ---: | --- |
| full-D-1（4 worker） | 407 | 401 | 6 | 390 | 898.00 | 0.4465 | 12.02 / 48.03 / 120.00 |
| full-A-1（1 worker） | 407 | 399 | 8 | 388 | 1619.58 | 0.2464 | 27.81 / 57.03 / 120.00 |

全量成功页吞吐 D/A=1.813（约 +81.3%），批次时间减少约 44.6%，P95 下降约 15.8%。
A 超时页为 81～88；D 超时页为 81、84、121、124、145、146。D 新增超时的
121/124/145/146 在 A 中分别 17.27/25.22/31.92/32.20 秒成功，不能仅凭失败总数
从 8 降到 6 就判定达标。全部 814 个页面尝试在代理中分别有唯一记录，没有自动重试；
状态为 A:399×200+8×499，D:401×200+6×499，真实负载无 413/502/504。

两组共同成功的 395 页中，尺寸、版面标签和坐标完全一致；101/104/234/350 页有正文
差异，字符序列相似度分别约 99.86%/98.18%/99.95%/99.97%。未对全部正文逐字验真，
不能宣称全文一致或 OCR 内容准确。结构校验通过与 OCR 内容正确是两个不同结论。

11 个严格质量失败页为
4、12、70、116、118、156、214、216、298、376、380，全部经源 PDF 核对为
文字、图片与内容流均为零的空白页；没有修改验证器掩盖这些结果。
401 个成功结果包含 18 个表格，18/18 通过 table/tr/td/th 标签配对及正数 rowspan/colspan
检查；该样本没有 seal，不能据此验证真实印章识别质量。

D 全量运行合计约 209.6 generation tokens/s、平均合计 Running 9.81，Waiting 始终为零。
各 rank GPU 平均利用率对应 GPU 2/3/4/5 为 73.6% / 42.8% / 39.2% / 37.6%，平均
48.3%；Pipeline GPU 1 为 5.6%。rank 负载并不均匀，不能把四卡均值当作每卡均已饱和。
A 全量合计约 116.2 generation tokens/s、平均合计 Running 2.41；VLM 四卡平均
利用率约 38.6%、Pipeline GPU 1 约 4.1%，Waiting 同样始终为零。
GPU 6/7 两组采样利用率始终为零。所有目标推理容器 restart count 均为零；
按组计划重建 worker 与引擎崩溃重启分开记录。

独立页面统计语义：
每页仍为 120 秒且不重试，其他异常或共享后端健康检查失败立即停止。
只统计独立页面终态，不组装或输出伪成功的完整文档。

## 协议、网关与交付门槛

- 本地无 PowerShell，按 check.ps1 逐项等价执行 harness lint、Ruff format/check、
  离线 pytest、Bash syntax 和 diff check；最新离线测试 52 passed。
- Docker Compose 二/四 worker 配置已校验；Ascend+replicas 在调用 Docker 前被显式拒绝。
- 归档前重新检查远端 Compose 状态：API、Nginx、4 个 Pipeline 和 VLM 均 healthy。代理合成边界检查中，16 个无效 JSON 请求均返回 422，记录覆盖四个 upstream；超出 64 MiB 限制的请求返回 413。
- worker 断开后，Nginx 动态 DNS 在合成请求到达前移除了该 upstream，因此没有得到 502 故障样本。自动分配的 Docker 网络不支持本次脚本尝试的静态 IP 重连；拓扑已恢复且四 worker healthy，但 DNS 换 IP 恢复不记为通过。网关 CLI/API smoke 未运行。
- 原始每页归一化结果、时延、指标及诊断只保存在 T4 `output/smoke/`；输入拆页在
  `tmp/pdfs/`。本报告不包含文档正文、Base64 或完整模型响应。

## 复测与恢复

```bash
BENCHMARK_CONTINUE_TIMEOUTS=1 bash scripts/run_replicas_benchmark.sh D full-D all 1
BENCHMARK_CONTINUE_TIMEOUTS=1 bash scripts/run_replicas_benchmark.sh A full-A all 1
```

实验模式由 `CONTRACTLENS_PIPELINE_MODE=replicas` 显式选择；四副本另设置
`CONTRACTLENS_PIPELINE_WORKERS=4`。默认单 Pipeline Compose 没有被替换。
恢复原模式使用原环境变量运行 `bash scripts/docker.sh up`，由统一生命周期移除实验 worker。
正式开放流量仍需明确过载拒绝、排队上限及错误映射；本轮只限制测试客户端在途数。
